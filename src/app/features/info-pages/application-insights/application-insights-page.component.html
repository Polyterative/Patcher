How we count

Top modules — public modules ranked from community ownership signals. Top 6 per bucket, minimum count 1. Buckets below that threshold show the empty note instead of a ranking.

Fresh this month — daily counts of public-profile updates — public modules, shared racks, and connected public patches. Window: last 30 days only; no long-range trend is implied. The New-this-week strip reads the first two module-freshness cohorts (0–7 days, 8–30 days).

Makers to explore — Most-collected ranks makers by public modules all-time; Heating up ranks makers by public modules updated in the last 30 days. Only makers with at least one module are shown; empty results are suppressed.

What fits your case? — public modules grouped by format standard, all-time counts.

What size? — public modules grouped from the HP-band distribution into Tiny (0–5 HP), Classic (6–16 HP), and Big (17+ HP). Median width is the catalogue median.

Library now — point-in-time totals from the cached public snapshot. Absolute counts of the all-time footprint — not rates, not a 30-day window. The starter line reads shared-rack and connected-patch totals from the sharing mix.

Private footprint — point-in-time global totals from the cached public snapshot. Public racks are shared racks on public profiles; private is everything else (unshared racks plus shared racks on private profiles). Counts only — no private contents, names, or owners are exposed. Shares hide until totals reach 10 with at least 3 per slice. Patches count connected works only (≥1 saved cable connection); unconnected drafts are in neither slice. Modules have no profile gate.

30-day activity — 30-day totals from the same public activity series as the Fresh chart above. Population: public modules, shared racks on public profiles, connected public patches.
